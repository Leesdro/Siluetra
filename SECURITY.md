# Security

The preferred security-reporting method is GitHub Private Vulnerability Reporting, when supported and enabled for this repository. From the [repository Security page](https://github.com/contactodrosel-dot/Siluetra/security), choose **Report a vulnerability** to submit a private report. Do not post secrets, private documents or exploit details in public issues.

At this update, the repository is private and Private Vulnerability Reporting is unavailable. GitHub currently supports enabling it for public repositories; see [GitHub's configuration instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository). Maintainers should enable it when the repository becomes public. Until a private reporting channel is available, use an already established private channel with the maintainers; if none exists, request a private contact method without disclosing vulnerability details. This policy does not publish a personal email address.

Include affected version, browser/OS, fictional reproduction and impact. Maintainers reproduce privately, coordinate a fix and disclose appropriately. No response-time guarantee is offered.
